# Decisions

One short note per decision that shapes the project. Add new ones with the next number.

| # | Decision | Why |
|---|---|---|
| 0001 | Input is **sprite -> animation**; text -> sprite comes later as a separate first stage | Artists keep their own art; a copy-based model can stay tiny; no open tiny model does this yet |
| 0002 | Train only on **permissively licensed** art (CC0, CC-BY, OGA-BY). Multi-licensed art qualifies through its permissive option | Weights can be Apache-2.0 without the share-alike question. Excludes the muscular and pregnant LPC bodies |
| 0003 | **Both 64x64 and 32x32**; 32 is derived from 64 renders | One source of truth; LPC is drawn at 64 |
| 0004 | **All LPC actions** (15), variable frame counts | Adding actions later only costs data |
| 0005 | **PyTorch with MPS**, export to ONNX | Simple path to a browser demo; same stack as tiny-voca |
| 0006 | Name: **moviepix** | Chosen by the maintainer |
| 0007 | Child body left out for now | It lacks 9 of 15 actions and has almost no permissively licensed clothing |
| 0008 | Datasets stored as one indexed-color PNG per character (all actions) | Lossless, ~100 KB per character instead of ~250 KB; max 65 colors seen |
| 0009 | 32x32 = majority color per 2x2 block, ties to the local average color | "Darkest wins" turned faces dark; this keeps fills and only uses original colors |
| 0010 | **Local-first** is a hard requirement; see [local-first.md](../local-first.md) | The project's point is AI that runs on ordinary computers |
| 0011 | Main model copies **by position** with **global** attention over the sprite's opaque pixels | Patterns move together; handles big moves (weapon swings); keys only over opaque pixels keeps it cheap |
| 0012 | **Iterative (MaskGIT-style) decoding**, trained with random masking so one model also does one-shot (`steps=1`) | Coherent results when motion is uncertain; enables variations, editing and the later text -> sprite stage |
| 0013 | Finding: **copy-by-color (B) loses to the U-Net (A)** at 32 px: pixel_exact 0.451 vs 0.506, alpha_iou 0.968 vs 0.989, palette fidelity 0.978 vs 0.565 | B moves bodies right but swaps whole regions to a similar-role color; choosing colors by value is not enough. Supports copying by *position* (C). Watch C's silhouette: B's single "transparent" class was weaker than A's separate alpha |
| 0014 | Dataset v1 sampling fixes for v2: eyes slot 0.7 -> 0.02, shields limited to whole shields, `*_trim` overlay items (hats, capes, shields) never drawn alone | v1 made 70% of characters cyclopes (LPC's eyes folder is only cyclops eyes) and ~11% carried floating heater-shield paint/pattern layers. A, B, C at 32 px all use v1, so their comparison stays fair; the 64 px run and later use v2 |
| 0015 | Result: **C wins** at 32 px. Validation pixel_exact 0.774 one-shot / 0.765 in 8 rounds vs A 0.506, B 0.451; unseen items 0.757 / 0.749; palette fidelity 0.986; CPU 16 ms / 119 ms for 8 frames | Copying by position works. Open: silhouette IoU 0.980 (one-shot) / 0.973 (8 rounds) still below A's 0.989, and 8 rounds does not yet beat one-shot on per-pixel scores (early commits can lock in errors; coherence is not measured by these metrics yet). Next: 64 px run on dataset v2, then a separate alpha decision and a coherence metric |
| 0016 | Result: **C at 64 px** (dataset v2, 36k steps x 4 examples = 144k examples, ~7.5 h on a MacBook Air): validation pixel_exact 0.758 one-shot / 0.695 in 8 rounds, unseen 0.753 / 0.690, silhouette 0.955 / 0.910, CPU 117 ms / 888 ms for 8 frames | Nearly the 32 px accuracy from a quarter of the examples, and one-shot meets the 200 ms target. 8-round decoding is clearly worse and too slow at 64 px: the decoding schedule commits background first and the character last. Fixing iterative decoding (schedule, confidence rule) is the next model task |
| 0017 | Decoding experiments (32 and 64 px, `scripts/decode_experiments.py`): "most confident first" commits background first and leaves the character to the last round (64 px, 8 rounds: 0.701 exact). **Random order** matches training and nearly closes the gap (0.749; 4 rounds 0.751) but no order beats one-shot (0.754). New coherence metric shows outputs have ~20 *fewer* single-pixel details per frame than the truth (over-smoothing). Default order is now `random`; one-shot is the recommended mode | Iterative decoding only helps once the model is trained on its own partial results (self-conditioning). Planned next run: self-conditioned masking + a separate alpha output |
| 0018 | Next model run: warm start from the first 64 px model; **self-conditioned training** (40% of frames get the model's own most confident predictions as "already decided"); **separate alpha output** for silhouettes; runs with `nice`, 2 CPU threads and 1 data worker so the Mac stays usable | Targets the two problems found in 0017: iterative decoding never learned to use its own partial results, and silhouettes lag the U-Net baseline. Warm start halves the run (~4.5 h) |
